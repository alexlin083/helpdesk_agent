# 一鍵部署操作手冊（deploy/hd）

把 helpdesk_agent 部署到 AWS Lightsail，只需要在 Mac 依序執行三個指令：

```bash
./deploy/hd build                       # 1. 測試、建置前後端 image、產生版本號
./deploy/hd push main-2026.11.20.1      # 2. 上傳到 Lightsail（尚未上線）
./deploy/hd deploy main-2026.11.20.1    # 3. 正式上線
```

這套流程參考公司 `docker.build` 與 `ecs-utils` 的做法：每次 build 產生一個版本號，並打成 git tag，上傳和部署都指定這個版本號；上線前的版本保留為 `prod-rb`，可以隨時換回。不同的是，公司的 image 推到 AWS ECR，這個專案沒有 image registry，所以改成直接傳到 Lightsail 主機。

> 這份手冊只說明日常更新流程。第一次建立 Lightsail 主機、網域、HTTPS 和主機上的 `.env`，請見 [Docker 與 Lightsail 部署操作手冊](Docker與Lightsail部署操作手冊.md) 第 3、4 節。

## 1. 先理解幾個概念

| 名詞 | 說明 |
| --- | --- |
| 版本號（tag） | 格式是 `<分支>-<yyyy>.<mm>.<dd>.<當天第幾次 build>`，例如 `main-2026.11.20.1`；日期以台北時間為準，月和日都補零；同一天 build 第二次就是 `.2`。分支名稱裡的 `/` 會換成 `-` |
| 兩個 image | 前端 `helpdesk-web`（Caddy：HTTPS、網頁檔案、轉送 API）和後端 `helpdesk-backend`（Node：API、AI、SQLite）。三個指令會把兩個 image 當成一組處理：同一個版本號、一起上傳、一起上線、一起回滾 |
| git tag | `build` 成功後，會在 GitHub 建立同名的 tag，所以從版本號就能查到是哪個 commit |
| `latest` | 主機上 `compose.yaml` 固定使用 `:latest`；部署就是把指定版本設成 `latest` 再重建容器 |
| `prod-rb` | 部署前正在執行的版本，用來回滾（rollback）；名稱沿用公司的 `prod-rb` |
| 版本顯示 | 版本號和 commit 會寫進 image；管理頁標題下方會顯示「版本：main-2026.11.20.1 · commit 5379ed0」，後端啟動日誌 `server.started` 也有 `version` 和 `commit` |

## 2. 第一次使用前的設定（每台電腦只要做一次）

### 2.1 需要的工具

| 工具 | 用途 | 檢查方式 |
| --- | --- | --- |
| Docker Desktop | 建置 image | `docker version` 要同時有 Client 和 Server |
| Node.js 22 | 執行測試（`build` 會自動嘗試 `nvm use 22`） | `node -v` 顯示 v22.x |
| Git，並能推送到 GitHub | 建立並推送版本 tag | `git push` 可以正常執行 |
| Lightsail 的 SSH 私鑰 | 上傳與部署 | 向負責部署的同學取得；**不要放進專案資料夾，也不要傳到聊天室** |

### 2.2 建立連線設定檔

```bash
cp deploy/hd.env.example deploy/hd.env
```

用編輯器打開 `deploy/hd.env`，填入：

| 設定 | 說明 |
| --- | --- |
| `HD_HOST` | Lightsail 的固定 IP（Static IP） |
| `HD_SSH_KEY` | SSH 私鑰的路徑，例如 `~/.ssh/helpdesk-lightsail.pem` |
| `HD_USER` | 預設 `ubuntu`，通常不用改 |
| `HD_REMOTE_DIR` | 主機上的部署目錄，預設 `helpdesk_agent`（也就是 `~/helpdesk_agent`），通常不用改 |
| `HD_KEEP_VERSIONS` | 主機上保留幾個版本，預設 5；每個版本約 130 MB |

`deploy/hd.env` 已經列在 `.gitignore`，不會被 commit。這個檔案只放連線資訊，不放密碼或 API 金鑰；正式站的金鑰只存在主機的 `.env`。

私鑰權限必須是 600，否則腳本會拒絕執行：

```bash
chmod 600 ~/.ssh/helpdesk-lightsail.pem
```

### 2.3 確認可以連線

```bash
./deploy/hd status
```

看到容器狀態和「執行中（latest）」的版本，就代表設定完成。如果出現「連不上 Lightsail 的 SSH」，請照第 4 節修改防火牆。

## 3. 部署三步驟

部署前，請先把要上線的程式碼合併到 `main` 並推送到 GitHub，然後在本機切換到 `main` 並 `git pull`。

### 步驟 1：build

```bash
./deploy/hd build
```

| 順序 | 做什麼 | 失敗時 |
| --- | --- | --- |
| 1 | 確認沒有未 commit 的修改，本機分支與 `origin` 同步，Docker 正在執行 | 依提示先 commit、`git pull`／`git push`，或開啟 Docker Desktop |
| 2 | 算出版本號並詢問是否繼續；如果這個 commit 已經有版本號，就沿用並重新建置同一版 | — |
| 3 | 執行後端、前端測試（Node.js 22）；失敗時會自動重跑一次，排除已知的偶發失敗 | 兩次都失敗就中止，並顯示失敗的測試 |
| 4 | 建置 `helpdesk-backend:<版本>`、`helpdesk-web:<版本>`（linux/amd64），把版本號、commit 和分支寫進 image | 遇到 Docker Hub `EOF` 時，會提示你重新啟動 Docker Desktop |
| 5 | 確認兩個 image 的架構和版本標籤 | — |
| 6 | 建立 git tag，並推送到 GitHub | 推送失敗時，依提示手動執行 `git push origin <版本>` |

最後會顯示下一步要執行的指令，例如 `./deploy/hd push main-2026.11.20.1`。

### 步驟 2：push

```bash
./deploy/hd push main-2026.11.20.1
```

| 順序 | 做什麼 |
| --- | --- |
| 1 | 確認本機有這個版本的兩個 image，而且是由 `build` 建置的 |
| 2 | **檢查防火牆**：顯示筆電目前的對外 IP，並實際試連 SSH；連不上就停下來，說明要怎麼改（第 4 節） |
| 3 | 上傳主機端輔助腳本，以及這個版本的 `compose.yaml`、`.env.example`（從 git tag 取出） |
| 4 | 把兩個 image 打包壓縮後上傳，在主機上載入，並核對 image ID 與本機一致；成功後刪除主機上的壓縮檔 |

push 完成時**正式站還沒有改變**，可以挑適當的時間再 deploy。

### 步驟 3：deploy

```bash
./deploy/hd deploy main-2026.11.20.1
```

| 順序 | 做什麼 |
| --- | --- |
| 1 | 再檢查一次防火牆 |
| 2 | 比對這個版本的 `.env.example` 和主機 `.env` 的**設定名稱**（不讀值）；主機缺少設定時列出名稱，並詢問是否繼續 |
| 3 | `compose.yaml` 有變更時顯示差異，確認後先備份成 `compose.before-<版本>.yaml` 再套用 |
| 4 | 詢問是否上線（網站會中斷約十幾秒），然後把目前版本保留為 `prod-rb`，把新版本設成 `latest`，重建容器並等待健康檢查 |
| 5 | 從啟動日誌確認版本號正確，沒有啟動失敗，並列出 AI 供應商、模型、資料庫結構版本等重點 |
| 6 | 清理舊版本：保留最近 `HD_KEEP_VERSIONS` 個版本，目前版本和 `prod-rb` 一定保留 |

**如果新版本沒有通過健康檢查**，腳本會顯示後端日誌，並詢問是否立即回滾到 `prod-rb`；這次部署換過 `compose.yaml` 的話，也會一併還原舊檔。

deploy 完成後，請開管理頁確認標題下方的版本號，並實際操作一次「自動生成」。

## 4. 換網路後 SSH 連不上（防火牆 IP）

Lightsail 防火牆的 SSH（TCP 22）規則只允許**一個 IP**（`/32`）。筆電換了網路，例如從家裡換到學校或手機熱點，對外 IP 就會改變，SSH 也會連不上。`push`、`deploy`、`rollback`、`status` 一開始都會自動檢查，連不上時會顯示：

```text
❌ 連不上 Lightsail 的 SSH（x.x.x.x:22）。最常見的原因是筆電換了網路、對外 IP 變了。
  請到 Lightsail 主控台 → 你的 instance → Networking → IPv4 Firewall：
    1. 點 SSH（TCP 22）那一列的鉛筆圖示
    2. 把來源 IP 改成 203.0.113.9/32，保留「Lightsail browser SSH」的勾選
    3. 按 Save，等幾秒後重新執行：./deploy/hd push main-2026.11.20.1
```

照著修改後，重新執行同一個指令即可。注意：

- **不要**把來源改成 `0.0.0.0/0`（全世界都能嘗試連線）。
- HTTP（80）和 HTTPS（443）的規則不用動。
- 多人輪流部署時，每次部署的人都要把規則改成自己的 IP。

## 5. 回滾

```bash
./deploy/hd rollback                      # 換回 prod-rb（部署前的版本）
./deploy/hd rollback main-2026.11.19.2    # 換成主機上指定的版本
```

- 回滾時，目前的版本會變成新的 `prod-rb`，所以連續執行兩次 `rollback` 會換回原本的版本。
- 只能換成主機上還保留的版本，可以用 `./deploy/hd status` 查看。已經被清理掉的版本，可以切換到那個 git tag 重新 build、push，再 deploy。
- 回滾不會修改 `.env` 和資料庫。新版本如果升級過資料庫結構，舊版本可能無法開啟；要先確認相容性，見 [Docker 與 Lightsail 部署操作手冊](Docker與Lightsail部署操作手冊.md) 第 5.2 節。

## 6. 查看狀態

```bash
./deploy/hd status
```

會顯示容器狀態、執行中的版本、`prod-rb` 的版本、主機上可部署的版本（由新到舊）和磁碟空間。

## 7. 選項

| 選項 | 用途 |
| --- | --- |
| `-y`、`--yes` | 略過所有確認問題（自動同意）；正式上線建議不要使用 |
| `--skip-tests` | `build` 時略過測試，不建議使用 |
| `--force` | `deploy` 時，即使已經是該版本也重建容器 |

`./deploy/hd help` 會顯示指令摘要。

## 8. 常見問題

| 狀況 | 原因與處理 |
| --- | --- |
| `build` 顯示「有尚未 commit 的修改」 | image 必須對應一個確定的 commit。請先 commit 或 `git stash` |
| `build` 顯示「與 origin 不同步」 | 本機分支和 GitHub 不同步，請先 `git pull` 或 `git push` |
| `build` 顯示 Docker Hub `EOF` | Docker Desktop 內部的網路代理卡住了，常發生在換網路或睡眠喚醒後。從選單列的鯨魚圖示 Quit Docker Desktop，重新開啟後再 build；不需要修改 Docker Desktop 的設定 |
| 測試需要 Node.js 22 | 執行 `nvm install 22 && nvm use 22` |
| `push`／`deploy` 顯示連不上 SSH | 見第 4 節 |
| SSH 私鑰權限錯誤 | `chmod 600 <私鑰路徑>` |
| `deploy` 列出 `.env` 缺少的設定 | 新版本的範本多了設定。先看規格書或 README 是否為必填：必填就先 SSH 到主機修改 `~/helpdesk_agent/.env` 再 deploy；有預設值的可以選擇繼續 |
| `deploy` 顯示「已經是這個版本」 | 正式站已經是該版本；要強制重建請加 `--force` |
| 管理頁顯示「前端版本…與後端不同」 | 兩個 image 不是同一次 build 部署的。重新執行同一版本的 `deploy --force`；只有手動操作 docker 時才會發生 |
| 管理頁顯示「版本：未標記（本機開發）」 | 執行的是本機 `npm run dev`，或不是用 `./deploy/hd build` 建置的 image |
| 主機空間不足 | 調小 `HD_KEEP_VERSIONS`；`status` 會顯示磁碟用量 |

## 9. 不在自動化範圍內的事

下列事項仍要手動處理，各自的說明見對應文件：

- 修改主機上的 `.env`（金鑰、模型、網域等）。改完後要讓設定生效，可以執行 `./deploy/hd deploy <目前版本> --force`。
- 資料庫備份與還原：[Docker 與 Lightsail 部署操作手冊](Docker與Lightsail部署操作手冊.md) 第 6 節。
- 第一次建立主機、網域與 HTTPS：同一份手冊的第 3、4 節。
- Google 行事曆的 OAuth 用戶端設定：[Google 行事曆連接設定手冊](Google行事曆連接設定手冊.md)。

## 10. 檔案與主機目錄

| 位置 | 內容 |
| --- | --- |
| `deploy/hd` | 本機指令：build、push、deploy、rollback、status |
| `deploy/hd-remote.sh` | 主機端輔助腳本；每次執行時都會自動上傳到主機的 `~/helpdesk_agent/.hd/`，不需要手動安裝 |
| `deploy/hd.env.example` | 連線設定範本；複製成 `deploy/hd.env`（不進 Git） |
| `backend/src/config/buildInfo.js` | 後端讀取版本資訊（`HELPDESK_VERSION`、`HELPDESK_COMMIT`、`HELPDESK_BRANCH`） |
| `frontend/src/version.js` | 前端版本資訊；版本控制中的內容是 null，建置 web image 時會覆寫 |
| 主機 `~/helpdesk_agent/.hd/releases/<版本>/` | 每個版本的 `compose.yaml` 與 `.env.example`（deploy 時用來比對） |
| 主機 `~/helpdesk_agent/compose.before-<版本>.yaml` | deploy 換掉 `compose.yaml` 前的備份 |

## 11. 從舊的手動流程改用這套指令

- 第一次 `deploy` 時，主機上原本的 image 沒有版本標籤，`prod-rb` 會顯示為「未標記」，但仍然可以用 `./deploy/hd rollback` 換回。
- 以前手動加的回滾標籤，例如 `pre-claude`、`pre-calendar`、`pre-holidays`，不會被自動清理。確認不再需要後，可以在主機上用 `sudo docker rmi helpdesk-backend:<標籤> helpdesk-web:<標籤>` 移除。
- 主機上以前留下的 `helpdesk-images*.tar` 也可以刪除，新流程不會使用。
