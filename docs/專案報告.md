# 企業智慧服務台 Agent — 轉案進度報告

> 報告日期：2026-11-07　｜　分支：`alex.revision`　｜　正式網址：`https://alex-lin-lab.com/helpdesk/`

**一句話介紹**：員工輸入需求主題，按「自動生成」後由 AI（Gemini，失敗時自動改用 Claude）判斷需求類型與處理部門、查詢公司資料（例如代理人、假別剩餘時數）並協助填單，送到負責部門後由部門成員簽核、退回、轉單或取消。整套系統以 Docker 部署在 **AWS Lightsail**。

- **文件**：API 介面規格書、部署操作手冊、需求類型規範皆由組員撰寫並隨程式同步更新（規則見 `AGENTS.md`）。開發過程使用 AI 程式助理輔助撰寫與審查程式碼，產出均經組員檢查與測試。

## 2. 執行架構規劃與設計（含與作業 1 的差異）

### 2.1 目前架構（AWS Lightsail）

```text
使用者瀏覽器
   │ HTTPS（443）
   ▼
┌──────────────── AWS Lightsail（Tokyo, Ubuntu 24.04, 1 GB RAM, Static IP）────────────────┐
│  Docker Compose                                                                       │
│  ┌─────────────── web 容器（Caddy）───────────────┐                                      │
│  │ /helpdesk/        → 前端 HTML / CSS / JS        │  自動申請、更新 HTTPS 憑證             │
│  │ /helpdesk/api/*   → 反向代理 ──────────────┐    │                                      │
│  └─────────────────────────────────────────── │ ──┘                                      │
│  ┌─────────────── backend 容器 ────────────── ▼ ──┐       ┌──────────────┐               │
│  │ Node.js 22 + Express 5（單一程序）              │ ────▶ │ Gemini API   │ 主要供應商      │
│  │  ├ 登入（JWT）、限流與配額                       │       └──────────────┘               │
│  │  ├ 需求類型引擎（JSON 設定驅動）                  │ 失敗時 ┌──────────────┐               │
│  │  ├ 自動生成 Agent（工具呼叫）                     │ ────▶ │ Claude API   │ 備援供應商      │
│  │  └ SQLite（better-sqlite3, WAL）                 │       └──────────────┘               │
│  │      └ /app/storage/helpdesk.db → Docker volume  │                                      │
│  └──────────────────────────────────────────────────┘                                      │
│  防火牆：只開 22（限管理 IP）、80、443                                                      │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

**AWS 使用說明**

| AWS 項目 | 設定 | 理由 |
| --- | --- | --- |
| Lightsail Instance | Linux/Unix → OS Only → Ubuntu 24.04、1 GB／40 GB SSD、Tokyo 區域 | 固定月費（約 US$7≈NT$231），在 NT$500 預算內還能留給 AI 費用 |
| Static IP | 掛載到 instance | 主機重開後 IP 不變，DNS 不用一直改 |
| 防火牆 | TCP 22 只限管理者 IP；80、443 對所有人 | 3000、8080 等內部 port 一律不開放 |
| 網域與 HTTPS | DNS A 記錄指向 Static IP，Caddy 自動申請憑證 | 前後端同一個網址，免設定 CORS 跨站 |
| 不使用的服務 | EB、CloudFront、ALB、NAT Gateway、DynamoDB、RDS | 課堂規模單台主機就夠，降低成本與設定複雜度 |

### 2.3 與作業 1 的改變（重點）

| 面向 | 作業 1（2026-10-14～10-17） | 目前版本 | 改變原因 |
| --- | --- | --- | --- |
| **系統定位** | 知識庫問答聊天 Agent：問問題 → 回答＋判斷 intent | **需求單（工單）系統**：AI 協助填單 → 送部門 → 簽核 | 從「回答問題」走向「真正處理需求」 |
| **AI 方式** | RAG：Gemini embedding 向量檢索 Top-3 文件，再由 Gemini 產生 JSON 決策 | **Agent 工具呼叫**：AI 依需要查同事、假別餘額、部門名錄；伺服器驗證欄位 | AI 能取得真實資料，結果可被驗證 |
| **AI 供應商** | 只有 Gemini | Gemini 為主、**Claude 自動備援**（失敗即切換，60 秒冷卻） | Gemini 常回 503／504 |
| **部門判斷** | 4 種 intent 對應 3 個部門＋關鍵字 P1 規則 | 8 個部門、7 種需求類型，**由 JSON 設定檔驅動**，新增類型不必改程式 | 擴充性 |
| **資料儲存** | 記憶體；正式環境規劃用 DynamoDB 存配額 | **SQLite**（需求單、帳號、員工、假別額度、人資調整），Docker volume 保存 | 需要持久保存工單，且不需另付雲端資料庫費 |
| **前端頁面** | 登入頁＋聊天頁 | 登入、提出需求單（含自動生成視窗）、狀態追蹤（申請／待辦／已完成）、管理頁 | 需支援簽核流程與營運監測 |
| **AWS 部署** | 規劃 GitHub Pages（前端）＋ Elastic Beanstalk（後端）＋ DynamoDB＋ IAM，可能再加 CloudFront | **單台 Lightsail ＋ Docker Compose ＋ Caddy**，前後端同網址 | 成本可預估、設定項目少、可在 Mac 先完整驗證 |
| **維運** | 無 | 健康檢查、優雅關機、日誌輪替、備份／還原／匯出腳本、人員管理腳本 | 讓同學實際使用時可維護 |

## 3. 遇到的困難與克服方式

| # | 困難 | 克服方式 | 狀態 |
| --- | --- | --- | --- |
| 1 | **Gemini 回應慢又不穩**：`gemini-3.5-flash` 實測單次 3～59 秒，7 回合只有 2 回合成功，其餘 503／504／429 | 改用 `gemini-3.5-flash-lite`＋低思考等級（每次 1.2～2.0 秒，7 回合全部成功）；再加 Claude 自動備援；期限由 20 秒延長到 60 秒、前端等待 70 秒 | ✅ 本機已解決，待正式站驗收 |
| 2 | **舊模型下架**：`gemini-2.5-flash` 回 404 | 模型名稱改用環境參數設定，404 也會觸發 Claude 備援 | ✅ |
| 3 | **作業 1 的 AWS 架構太複雜**：EB＋DynamoDB＋IAM＋CloudFront 設定多、費用不易估、本機無法完整模擬 | 改為 Lightsail 單台主機＋Docker Compose；同一份 Compose 在 Mac 與雲端都能跑 | ✅ |
| 4 | **JSON 檔存工單**：多人同時寫入會互相覆蓋 | 改 SQLite（WAL 模式、單一連線、交易），提供舊 `tickets.json` 自動匯入 | ✅ |
| 5 | **better-sqlite3 原生模組**：需 Node 22.14 以上，Docker 建置時要編譯 | 全組統一 Node 22.23.4（`.nvmrc`）；Dockerfile 建置時安裝編譯工具、完成後移除，並在建置階段驗證載入 | ✅ |
| 6 | **學校 Wi-Fi 共用 IP**：全班可能被當成同一人限流 | 配額改以帳號（userID）計算，IP 層只擋異常大量；`TRUST_PROXY` 只信任 Caddy 一跳 | ✅ |
| 7 | **AI 不能亂寫資料**：擔心 AI 看到他人個資或自行修改資料庫 | AI 只能透過白名單工具讀資料（`self_only`／`same_department`／`names_only` 權限）；所有欄位由伺服器再驗證 | ✅ |
| 8 | **密碼與金鑰外洩風險**：早期文件曾寫入登入密碼 | 移除文件中的密碼，改由未追蹤的 `.env` 提供；production 缺少密碼直接拒絕啟動 | ✅ |
| 9 | **前端快取舊檔**：Python `http.server` 不送快取標頭，改了 JS 沒生效 | 自寫 Node 靜態伺服器（`no-cache`），與正式 Caddy 行為一致 | ✅ |
| 10 | **限流計數存在記憶體**，重啟就歸零，也無法多台主機 | 課堂規模先接受單一程序 | ⚠️ 未完全解決 |
| 11 | **AI 費用無法即時監看**：管理頁只看得到請求次數，看不到 Token 與帳單 | 先用每日額度（每人／全站）控制上限 | ⚠️ 未完全解決 |

## 4. 目前完成的部分（展示）

**展示流程建議**（約 5 分鐘）

1. **登入**：`https://alex-lin-lab.com/helpdesk/` 以一般帳號登入。
2. **請假申請**：主題輸入「請假」→「自動生成」→ AI 說明由人力資源部處理；以一句話描述請假內容，AI 查詢可擔任代理人的同事、填入日期與假別，右側顯示「特休剩餘時數：前 → 後」→ 套用並送出。
3. **設備申請**：主題「申請螢幕」→ 數量填 0 或日期填過去，顯示「格式不符」→ 修正後送達總務與硬體組。
4. **簽核**：改用人資帳號登入「狀態追蹤 → 待辦表單」，簽核／退回／轉單。
5. **管理頁**：管理員查看限流用量、待簽核數量、資料庫筆數與大小。
6. **AWS**：展示 Lightsail 主機、Static IP、防火牆設定與 `docker compose ps`（backend healthy、web running）。

## 5. 未來改善方向

1. **通知功能**：目前「送達」只會出現在待辦清單，未來加上 Email／Slack／Teams 通知處理人與提單人。
2. **與公司既有系統整合**：簽核後自動扣除假別額度、串接 HR 或 ERP，而不是只改變需求單狀態。
3. **AI 成本與品質監測**：記錄 Token 用量與費用，並定期以評估資料集量測部門分類準確率。
4. **AWS 架構強化**：
   - 自動備份：Lightsail 自動快照，或排程把 SQLite 備份上傳 **Amazon S3**。
   - 監控告警：使用 Lightsail 指標告警（CPU、流量），或導入 **CloudWatch**。
   - 使用者變多時：升級 2 GB 方案；再進一步可將資料庫移到 **RDS**、限流計數移到 Redis，才能多台主機並行。
5. **CI／CD**：GitHub Actions 自動跑測試、建置 Docker image，並部署到 Lightsail。
6. **擴充需求類型**：例如查詢設備庫存、會議室預約，只需新增 JSON 定義（若需要新資料來源再新增能力）。
7. **安全性**：登出後撤銷 token、個別帳號密碼（目前一般帳號共用示範密碼）、SSO 登入。
