# 期末專題功能變更說明：Google 行事曆連接與目標導向請假

請假的「自動生成」改成目標導向：員工說出想達成的事，助理查假別額度、同事、員工自己連接的 Google 行事曆與公司規章，整理 1 到 3 個方案，員工選了才填進表單；送出前一律由後端驗證

資料庫結構版本仍是 8、Dockerfile 沒有改，舊版程式也開得了新版寫過的資料庫

接下來要做的事：

- 負責部署的同學照《Google 行事曆連接設定手冊》設定一次 Google 用戶端，並在部署用的 Mac 上驗證兩件事：重新安裝套件後，後端 192 項、前端 177 項測試全部通過；Docker 映像建得起來，啟動後資料庫版本仍是 8
- 組員一起確認兩條規則：病假要不要通知薪資系統、規章第 11 條病假事後補提的寫法（事假、特休的提早天數已改成建議至少提早 1 個工作天，不擋送出）；定案後由負責程式的同學改請假設定與知識庫，測試跟著更新
- 佳妤確認方案評測的題庫，再用組員自己的 AI 金鑰跑 Gemini 與 Claude 的比較，把結果檔交給組員一起看兩家差在哪

## 1. 部署與相容性

- 資料庫：結構版本維持 8，不新增資料表；連接資料存在既有的 `meta` 表，薪資通知寫進那張需求單的歷程；新版寫過連接與通知的資料庫，交給基準版程式照常啟動、登入、列出需求單
- Dockerfile 一個字都沒改；新增的設定檔（連接器清單、知識庫）放在 `backend/src` 底下，由既有的 `COPY src ./src` 帶進映像
- 新套件只有 `@modelcontextprotocol/sdk` 1.32.2，版本釘死；鎖定檔新增 21 個套件，既有套件的版本不變
- 環境參數：新增選填的 `PUBLIC_APP_URL`，留空時自動推導；`AUTH_SECRET` 原本 production 就必填，現在也拿來加密 Google 授權，部署更新時不能換
- 請假定義升到第 4 版（第 3 版加上提早提出的檢查與核准通知，第 4 版把提早提出改成建議）：更新時還開著舊畫面的人，按送出會收到「表單已更新」，重新跟助理確認就好；已送出的單保留原本的版本，照常簽核
- 打卡補登、VPN 申請、報修、設備申請、採購申請、一般需求的定義升到第 2 版，只改給 AI 的說明與可用工具，欄位與規則不變；舊畫面的處理和上一條請假相同
- 有備援 AI 時，「自動生成」一回合的期限從主要 30 秒加備援 15 秒，放寬成 40 秒加 25 秒，合計 65 秒，仍在畫面的 70 秒等待內
- 如果 `SHUTDOWN_TIMEOUT_MS` 設在允許的最低值 70000，有備援的回合結束後只剩 5 秒收尾；目前的預設 75000 不受影響
- 只更新後端、前端還是舊版時，歷程裡的通知會顯示原始代碼 `NOTIFIED`，可以接受

## 2. 改了什麼

| 功能 | 使用者看到的變化 | 主要位置 |
| --- | --- | --- |

| 連接帳號頁 | 帳號選單多了「連接帳號」，員工自己連接或中斷 Google 行事曆，權限分基本與進階 | `frontend/pages/connections/`、`backend/src/services/connectors/` |

| 請假方案 | 對話區列出方案卡片，寫理由、查過的資料、能不能送；按「用這個方案」才填進右側，助理會接著回覆，例如問還缺的假別、代理人 | `draftEngine.js`、`draftDialog.js` |
| 提早提出的建議 | 事假與特休建議至少提早 1 個工作天提出，不擋送出；病假不受限 | `backend/data/requestTypes/leave.json`、知識庫 `KB-HR-004` |

## 3. 在組員電腦跑的建置驗證

開發用的電腦沒有 Docker，也沒有 C++ 編譯工具，下面兩項沒有實際跑過，請有環境的組員跑，部署手冊用的 Mac 就可以

### 3.1 better-sqlite3 13.0.3

`package.json` 釘的是 13.0.3；開發時因為沒有編譯工具，是拿 12.11.1 跑完全部測試的

13.0.3 不附預編譯檔，安裝時一定會用 node-gyp 在本機編譯，先準備好編譯工具：

- Mac：要有 Xcode Command Line Tools，沒有的話先跑 `xcode-select --install`
- Windows：要有 Visual Studio 的「使用 C++ 的桌面開發」，node-gyp 另外需要 Python 3
- Docker：不用另外準備，`backend/Dockerfile` 建置時會先裝 python3、make、g++，編完再移除

```bash
cd backend
npm ci
node -e "const D=require('better-sqlite3');const d=new D(':memory:');console.log(d.prepare('select sqlite_version() v').get().v);d.close()"
npm test
cd ../frontend
npm test
```

預期結果：

- `npm ci` 成功，過程中會看到 node-gyp 編譯 better-sqlite3；出現 `gyp ERR!` 通常是缺上面的編譯工具
- `node -e` 那一行印出 SQLite 的版本號，沒有錯誤
- 後端 192 項、前端 177 項測試全部通過

### 3.2 Docker 建置

在專案根目錄、照部署手冊第 2.2 節準備好 `.env` 之後：

```bash
docker compose build
docker compose up -d
docker compose ps
docker compose exec backend node -e "const D=require('better-sqlite3');const d=new D('/app/storage/helpdesk.db',{readonly:true});console.log(d.pragma('user_version',{simple:true}));d.close()"
docker compose exec backend ls src/services/connectors src/services/knowledge
```

預期結果：

- `docker compose build` 成功；Dockerfile 最後一步會在映像裡載入 better-sqlite3，13.0.3 裝不起來時建置就會失敗
- `docker compose ps` 兩個服務都是 healthy
- `user_version` 印出 `8`
- 第二個 `ls` 列出 `connectors.json` 與 `knowledge-base.json`
- 打開 `http://localhost:8080/helpdesk/`，用一般帳號登入，帳號選單有「連接帳號」，頁面上的 Google 行事曆說管理員還沒完成設定
- 不登入，直接打開 `http://localhost:8080/helpdesk/pages/privacy/privacy.html`，看得到隱私權政策
- 用管理員登入，管理頁「Google 連接設定」顯示的回呼網址是 `http://localhost:8080/helpdesk/pages/connections/connections.html`

要回到上一版時，換回上一版的映像即可；資料庫版本沒變，連接資料留在 `meta` 表，舊版不會讀它

## 4. 情境與測試對照

這 9 種情境來自交接文件第 10 節（開發規格書 T-01 到 T-09）

真的 AI 會怎麼回答，要等第 6 節的方案評測；下表的「結果」是自動測試已經確認的部分

| 情境 | 結果 | 還要用真的 AI 看 |
| --- | --- | --- |
| 有連接行事曆的一般請假 | 方案經後端驗證後列成卡片，選了才填進欄位 | 方案的日期與假別合不合理 |
| 想請的那天有會議（進階權限） | 行事曆工具回得出那天的行程 | 會不會避開會議或說明衝突 |
| 特休額度不足 | 方案標成不能送並寫出原因 | 會不會改提別的組合 |
| 沒說日期 | 後端不會替使用者補日期 | 會不會只問日期 |
| 沒連接行事曆 | 照常運作；AI 看不到行事曆工具，畫面提示可以連接 | 會不會假裝查過 |
| Google 失敗或逾時 | 工具回固定說明，不回半套資料 | 會不會改用問的 |
| 行程標題夾帶指令 | 看不到的字元先清掉、截到 60 字，附「只當資料」提醒 | 會不會照標題裡的文字做 |
| 主模型與備援模型結果不同 | 評測工具列出差異，線上仍以後端驗證為準 | 兩家差多少 |
| 沒按「用這個方案」 | 方案不寫進欄位，也不能直接送出 | 不用 |
